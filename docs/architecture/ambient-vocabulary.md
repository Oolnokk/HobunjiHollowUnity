# Floating-speech vocabulary

The vocabulary transformer is intentionally separate from the ordinary NPC Talk dialogue. Only text passed to `AmbientDialogue.show(root, text, options)` is eligible, and only if a speaker ID and a matching source word/phrase exist. The authored line is never rewritten in storage; the optional one-shot change happens before the bubble's canvas texture, cadence schedule, duration, speech ticks and debug event are created. NPC acceptance/refusal, greeting, social reaction and festival speech reuse that path. Player progression and normal Talk are excluded.

## Single master synonym catalog

`docs/config/dialogue/ambient-vocabulary.json` owns the **only** copy of synonym text. Source words and phrases are keys under `lexicon`. Each alternative has `id`, `text`, `verbosity`, `color`, and `formality`; those three registers are independent 0–100 values. An optional `kind` distinguishes `standard`, `regional`, `old-slang`, `simple`, and `near-miss`; historical slang also stores a `firstRecorded` year (strictly before 1900) and an evidence URL in `source`. A synonym's ID must remain stable when its displayed text is edited.

Each character's `characters.<npcId>.selections` stores **only checkbox references**, never a second list of synonym text. The shape is `{ "<source word>": ["<synonym id>", "..."] }`. A missing source word inherits that character's slider-generated choices. An explicitly present empty array means no substitutions for that word. The catalog is resolved to a short-lived render table when a speaker needs it, and is cached in memory for at most 128 distinct speakers. If a master synonym is renamed, every NPC who checked its ID automatically speaks the new text.

```json
{
  "lexicon": {
    "lovely": [
      { "id": "nice", "text": "nice", "verbosity": 20, "color": 35, "formality": 20 },
      { "id": "splendid", "text": "splendid", "verbosity": 65, "color": 65, "formality": 85 }
    ]
  },
  "characters": {
    "pahu": {
      "sliders": { "frequency": 70 },
      "selections": { "lovely": ["nice"] }
    }
  }
}
```

An existing `child` personality and a vocabulary-only `porakaneki` family provide separate starting presets. The named `porakaneki_chief` and dynamically generated `porakaneki_...` hunters resolve to the latter family without creating a duplicate reaction personality. Child-family NPCs (including generated `child_` IDs) prefer simplified and coined near-miss alternatives; adults with zero unusual-style sliders generate only standard entries. Manual checkboxes can still enable any globally approved entry for any character. The same single master entry can be checked by as many characters as needed. Legacy exported `character.table` word copies are converted to canonical IDs by the standalone editor on import, and can be read by the runtime for compatibility. Nonexistent IDs are ignored rather than converted to freeform text.

## Authoring in the standalone workshop

Open **Dev Tools → Vocabulary Workshop**. It is not embedded in the already crowded Ambient Dialogue Editor.

* **Master dictionary**: search any source word or phrase; author shared synonyms, three style coordinates and their stable IDs once; rename any synonym without invalidating the checks. A deleted synonym removes its existing checkmarks.
* **Personality family**: use the six independent defaults for the six existing shared reaction profiles.
* **Character**: inspect/check/uncheck every canonical alternative under a source phrase. The character's checkbox overrides apply per source word. Clear them to inherit generated defaults. Regenerating *all* checkmarks explicitly overwrites manual choices; the batch generator only initializes NPCs that have no manual choices.
* **Live preview**: experiment with an authored sentence using exactly the same runtime matcher and selected IDs. Import/export acts on **only** this vocabulary JSON, not dialogue, reactions or character data.

The nine sliders are **simplicity–verbosity**, **technical–colorful**, **casual–formal**, vocabulary breadth, variation, substitution frequency, **pre-1900 historical slang**, **over-simple wording**, and **almost-right wording**. A stable per-speaker ±12 point offset gives otherwise similar family members distinct starting ranges. Breadth varies both source word coverage and candidate count. Variation determines how many of those candidates are checked by default. Frequency determines the random chance to use any checked alternative when a line is displayed.

## Greeting and pet reaction coverage

The current authored greeting pools have 49 player-directed NPC source lines; before this pass, only 10 contained any master-dictionary source phrase. The six personality-owned pet reaction pools have 82 authored lines, only 16 of which previously contained a phrase. Canonical greeting/pet entries (e.g., `hello again`, `there you are`, `howdy`, `looking good`, `well-mannered`, `listens well`, `good morning`) now raise raw lexicon coverage to **35/49** greeting lines and **63/82** pet lines, without modifying the reaction/greeting pool selection code. Actual rendered changes still depend on a character's approved selections, style, and frequency. Sound effects and intentionally terse responses may remain unchanged.

Player/NPC greeting addressees and pet names/species are resolved before rewriting. The renderer passes its explicit greeting addressee and skips automatic pet-name lookup for ordinary NPC greetings; for pet remarks, the vocabulary engine obtains the three possible active pet identities directly from the public `StableAnimalProgression.activeEntryForRole` API and their `CREATURE_DB` species labels. **The stable-animal and NPC-reaction modules do not import vocabulary or need to supply new option fields.** It temporarily masks whole-name matches as already-supported brace placeholders, runs the same lexical and Pahu phonetic passes, then restores the exact names before rendering. This prevents pets named *Kitty*, or players named *Hi*, from having their identities rewritten. If a pet is named a common greeting word (for example, *Hi*), a leading `Hi, ...` is still treated as a greeting while subsequent occurrences of the pet's name remain protected. Explicitly addressed player/NPC names take priority. The optional protection runs once for an actual matching bubble; unmatched animal cries skip the lookup and no gameplay frame-update loop changes. This decoupling removes the vocabulary branch's edits to `stable-animal-progression.js`, `npc-silliness-reaction-runtime.js`, `character-action-locks.js`, `format-utils.js`, and `livestock-nursery-install-bridge.js`, avoiding those shared bootstraps and their frequent cache-version conflicts.

The greeting `{dayPart}` placeholder is resolved by the existing greeting system before the vocabulary pass. Time-specific phrases such as `good morning` and `good evening` therefore vary safely without changing unrelated usages of `good` (particularly the protected phrase `good to see you` for Kzubug and others). Character-specific selections keep Ginju Southern phrasing, Pahu's pirate diction, Gantami's childish reactions and Leaf's quiet voice intact. A full 131-line source audit now checks six substitution rolls per source line (786 trials), including preservation of placeholders and the correction of context-unsafe transformations such as `Hey-hey → Hello-hello`, `How long has → How much time has`, and `that tiny → that very little`. No new per-frame dialogue logic was introduced.

## Grammar, fallback and performance

Tokens such as `{targetName}` and `{{playerName}}` are protected. Matches respect Unicode whole-word/phrase boundaries and prefer longer source phrases. Capitalization is preserved. When a preceding `a` or `an` would obviously be invalid after substitution, the word is left as authored. This is a conservative spelling check, **not** full grammatical inflection, so authors should keep alternatives compatible with the source word's part of speech and sentence context. No online language model or thesaurus runs during gameplay.

An absent config, unmatched sentence, failed optional module, unrecognized synonym ID, or an excluded dialogue path always leaves the original line unchanged. A global source-word matcher skips per-speaker vocabulary work for most speech. The engine builds per-speaker tables **lazily on a matching bubble only**, caches them with a 128-speaker LRU, and never performs vocabulary work during the frame update.

`AmbientDialogue.getDebug().vocabulary` and `AmbientVocabulary.getDebug()` report readiness, last authored/displayed line, match/swap counts, and a bounded history of the **last 12 attempted floating bubbles**, each with an explicit reason such as `reworded`, `no-dictionary-phrase`, `engine-not-ready`, or `frequency-or-disabled-choice`. This is available from the existing in-game mobile diagnostics with no console or extra frame polling. Run `node scripts/test-ambient-vocabulary.js` to test shared references, controls, fallbacks, token protection, article agreement, and speech scope. Its real browser visuals should also be smoke-tested on mobile before merging.

## Historical slang and intentionally imperfect speech

The expanded lexicon contains **204 source words or phrases and 442 centrally authored alternatives**, including the previously approved pre-1900 slang entries. Examples include *balderdash* (nonsense by the 1670s), *humbug* (1751), *grub* (food from the 1650s), *chum* (1680s), *skedaddle* (1861), and *spondulicks* (1856); each tagged entry carries an etymology reference. The historical cutoff applies to **recorded English usage of the same sense**, not merely to words that look old. Modern slang (1900 onward) is deliberately excluded from automatic historical selection.

`simple` alternatives are intentionally plain or repetitious (*food* → *stuff to eat*); `near-miss` alternatives are invented, deliberately approximate childlike vocabulary (*mysterious* → *mystery-ish*, *blizzard* → *snow-fury*). The categories are independent: a Porakaneki can favor centuries-old slang without childish mistakes, and a child can prefer mistakes without slang. Setting a style slider to zero excludes that style from automatic generation. Manual checkmarks override the stylistic sliders, including deliberate exclusions; undated/post-1899 historical slang remains blocked until its evidence is corrected.

The three style coordinates and three unusual-speech sliders are independent. The gameplay runtime uses the exact same nine-axis normalization as this workshop; never maintain a second six-axis whitelist that would silently disable the unusual-word categories. Categorized alternatives first pass a stable per-speaker inclusion gate, then compete in the existing authored-style ranking. This keeps NPCs from acquiring identical speech automatically. Master Dictionary permits editing each entry's **style kind** and documented **first attested year** without changing its stable ID or removing any NPC checkbox.

Spelling-oriented grammar checks cannot reliably catch all shifts in meaning, article pronunciation, inflection or sentence framing. In particular, coined malapropisms are intentionally odd; authors should preview complete sample sentences before checking them for characters. The original ambient speech remains the fallback whenever an eligible replacement is unavailable.

## Ginju, Pahu and the doorstep voice corpus

The **Ginju** group resolves `gorobi_ginju`, `gikali_ginju`, `aliri_ginju`, `gantami_ginju` and future `*_ginju` IDs to the `southeastern-us` dialect. It inherits each NPC's existing reaction personality (playful, reserved, proper or child) and overlays regional phrases only: `isn't` / `aren't` → *ain't*, `I'm not` → *I ain't*, `you all` → *y'all*, *howdy*, *reckon*, *over yonder*, *tote*, *mighty*, and related traditional usages. The **Pahu** group independently enables `west-country` and `pirate`, with expressions including *ahoy*, *matey*, *aye*, *avast*, *gurt*, *dreckly* and *bain't*. These terms remain single entries in the global synonym dictionary; group and personal selection layers reference only their IDs. A regional entry with no configured dialect tag is excluded from automatic generation.

Pahu also has the **`pahu_grapple_flail` phonetic preset**, using ordered whole-phrase substitutions derived from his original trust-gift doorstep speech: *I → oy*, *my → moy*, *mind → moind*, *life → loife*, *time → toime*, *fight → foight*, *behind → behoynd*, *I am → oym*, *getting → gettin'*, and related letter patterns. The preset is applied once **after** semantic substitutions, only to Pahu's floating speech; it does not edit any authored Talk tree or another NPC's bubble. Terms are matched as complete words or phrases, so names and unrelated `-ing` nouns are left alone. This is the fictional character's *authored eye-dialect*, not a claim that all West Country speakers sound like him.

The standalone **Vocabulary Workshop** now provides distinct regional group panes with group slider overrides, editable comma-separated dialect tags, and Pahu's editable phonetic word pairs. Under a character, the **Authoritative doorstep speech** accordion reads the live data-only `WEAPON_TRUST_VISIT_CONFIG.gifts`: authored gift dialogues by Jubmir, Kzubug (including branched tree nodes), Hreesh, Pahu, Dzibim and Furunji. Original lines can be copied into the floating-speech preview without changing the source. The separate **Next authored greeting** button now cycles the selected NPC's actual game `npcGreetings.<id>.player` entries (one optional 25 KB JSON load on workshop startup), automatically showing their rewritten floating-speech preview with the current personality, dialect checkmarks and phonetic settings. It provides mobile-visible sample counts, and the source greeting JSON is never included in vocabulary exports. The **Harvest vocabulary candidates** section extracts previously unlisted words from those authored lines and allows individual one-tap addition as empty master dictionary entries. Nothing is automatically replaced until a synonym is authored or checked. Dynamic doorstep providers such as adoption and tutorials are not part of this read-only weapon-trust corpus; they remain intentionally unaffected.

Historical period note: *ain't* predates 1900 (American Heritage dates the contraction to 1778), *y'all* is recorded by 1879, *avast* is an older nautical command, and *ahoy* appears in naval use by the eighteenth century. See the per-entry `source` URLs; not every regionalism is labeled historical slang. Nautical pirate stereotypes and West Country dialect share some features but are not interchangeable, so Pahu's fictional accent follows his specifically authored doorstep text.


## NPC-source voice authoring audit (2026-11-22)

The character voice pass reads the canonical `docs/config/npcs/hobunji-starter-npc-database.json` **bios, jobs, schedules, original general-chat phrase pools and nicknames**, alongside authored trust-gift doorstep dialogue and the floating-reaction family definitions. It tunes `characters.<id>.sliders` and **canonical synonym checkboxes** for nine named speakers without changing their original Talk text. A new first-party greeting batch was authored under `npcGreetings.<id>.player` in `docs/config/dialogue/ambient-dialogue.json`, with 5–6 variants each for the four Ginjus and Pahu. All five retain their previous greeting and receive four or five additional brief, context-safe lines.

- **Pahu**: an elderly, silly, generous festival lover with a much more specific accent than “generic pirate.” Keep *Ahoy*, *moy*, *oym*, *foight*, *ye* and his sea-song/festival jokes, but disable `look at → hark at`, `big → gurt`, and stiff phrases that make casual exclamations sound unnatural. Include the two additional phonetic contractions `isn't/aren't → ain't`, matching his own authored use.
- **Gorobi Ginju**: friendly, proud agricultural patriarch who treats the player as a crop-growing rival. His new lines ask after harvests and cheerfully challenge the player; moderately colorful Southeastern vernacular and familiar *pal/chum* are appropriate.
- **Gikali Ginju**: kind, cautious, anxious farmer; substantially **less frequent** transformations, with concern about the player overworking rather than forced rustic jokes. Preserve `friend` and avoid breathless superlatives.
- **Aliri Ginju**: young, dutiful, teasing farmer. Her canonical phrase pool literally contains *“Mornin'”*, *“How's it goin'?”*, *“Bet I got more done today”* and the rivalry nickname. Change her **shared reaction assignment from `proper` to `playful`**, while setting her personal vocabulary to casual competition without copying Gorobi's style.
- **Gantami Ginju**: mischievous little boy. Prefer playful tricks, Papa/Mama, running games, and childlike near-miss words rather than automatically giving him every adult Southern expression.
- **Leaf, Hreesh, Kzubug and Jubmir**: keep Leaf terse, Hreesh blunt, Kzubug gentle and protective, and Jubmir caring and conversational. Restrict overly affectionate synonyms where they conflict with authored dialogue and keep the smith's existing `Good to see you safe` intact.

Semantic review removed or narrowed options that break **sentence agreement, social intent or adjective position**. In particular: `weather → the elements` broke `weather is`; `quiet → peaceful` changed a sound-level remark into a judgment about tranquility; `not right now → maybe later` implied a promise that wasn't made; `dangerous → not safe` damaged attributive adjective grammar; `certainly → without question` could produce stilted mid-sentence insertion; and `weapon → arm` was scoped to Pahu's pirate usage. The overarching rule is to leave the authored original unchanged rather than force an uncertain synonym.

`scripts/test-ambient-vocabulary.js` now reads the original 1.18 MB NPC database, verifies those bios and authored greetings, evaluates **four deterministic substitution rolls per line**, checks placeholder preservation, compares a curated set of individual voice snapshots, checks previous semantic failures, and exercises the editor. There is no gameplay frame-loop work; the new lines are tiny static data entries. The workshop can audition each character's authored greeting lines without needing developer tools. `ambient-dialogue.js` fetches the dialogue JSON once with `cache: 'no-store'` on startup, so returning players can load the revised copy without a stale browser-cache entry. Full in-browser/mobile presentation still requires a human smoke test.


## Player baby: ambient babble until toddlerhood

The player's **saved family children** use the authoritative `RomanceFamily.phaseOf` stages, not an appearance-derived age guess. From birth/adoption through the **basket** stage (the first 28 in-game days by default), all **ambient** speech from that NPC—proximity greetings, directed floating reactions and other calls to `AmbientDialogue.show`—is replaced with short **phonetic baby noises**, not English synonyms or narrated actions. The ten authored utterances in `docs/config/romance-config.js → family.babyAmbientNoises` include *Agoo!*, *Guh-buh!*, *Baba-ba!*, *Ahh-oo!*, *Mmm? Buh!*, and *Gah-gah!*. The existing normal mouth/syllable tick and chathead bubble renderer handles these sounds; there is no separate vocalizer, frame loop or text texture pipeline.

Infant greetings now opt in to the existing **five-times-per-second proximity scan** and its daily per-target greeting ledger. Baby speech is independent of adult relationship/name permissions and always skips the synonym/old-slang/phonetic-dialect generator. When the same baby is held in the player's hands, stowed on the player's back, or carried by a spouse, its ambient bubble anchors to the **existing registered `FamilyBabyBurdens` proxy**, not the invisible infant walker left near the basket. Thrown babies do not use the airborne proxy as an idle greeting origin. The baby retains normal harmless world chatter when resting in the basket or placed on the ground. Direct non-ambient Talk/quest dialogue still uses `DialogueContent` and remains unchanged.

At the exact **toddler** boundary (`bornRawDay + basketDays`), `babyAmbientSound` immediately returns `null`; the speech pool switches to short first-word greetings, e.g. *Da! Da!*, *Up! Up!*, *Hiya!*. Once a **child**, the original fuller child greetings return. The transition needs no reload: the family tick re-registers the pool only when its growth phase changes. A small runtime greetings registry survives the initial asynchronous ambient JSON load, and old child pools are cleared when loading another saved family.

On mobile, `AmbientDialogue.getDebug().lastBabySpeech` reports the last successfully rendered babble, infant speaker ID, whether a parent was carrying them, and the visual anchor's name. The existing `RomanceFamily.snapshot().children[].phase` reports the exact saved growth stage. The regression suites `scripts/test-ambient-vocabulary.js` and `scripts/test-family-baby-burdens.js` validate phonetic-only wording, exact 28-day stage boundaries, world reload, player/spouse arms and back-stow anchoring, and cleanup when becoming a toddler. Live mobile/WebGL visual confirmation is still recommended.


## Newborn ambient dialogue and toddler handoff

The player's family child uses the saved `RomanceFamily.phaseOf(child)` as its only age authority; `isBasketBaby(child.id)` is true strictly before `family.basketDays` (28 in-game days by default). The spoken bubble logic in `AmbientDialogue.show()` bypasses both the master synonym generator and adult/reaction dialogue for these newborn IDs. Instead, `RomanceFamily.babyAmbientSound()` chooses one of the short phonetic strings from `docs/config/romance-config.js` (`family.babyAmbientNoises`); examples include *Agoo!*, *Guh-buh!*, *Baba-ba!* and *Mmm? Buh!*. Ordinary scripted Talk is not intercepted.

The preexisting 5 Hz proximity greeting scheduler triggers these babbles using the usual cooldown/once-per-speaker-target/day ledger. The newborn has no adult Favor threshold or name-based greeting. Babbling from a visible baby in its basket or on the ground uses the actual child walker. When carried or stowed on the back of either parent, it follows the **existing** `FamilyBabyAmbientVoice.anchorFor(id)` visible group and its current map, rather than the hidden walker at the basket. While a proxy is airborne, hidden, or temporarily unavailable, neither spontaneous proximity greeting nor direct newborn `show()` can create a ghost speech bubble from the basket. The daily greeting ledger only advances **after** a newborn bubble actually renders; a missing scene can therefore recover normally.

At day 28, `RomanceFamily.syncChildAmbientGreetings` replaces the pool with the toddler's short intelligible first words (*Da! Da!*, *Up! Up!*, *Hiya!*, etc.). After the normal child phase begins, their original older-child greetings resume. Existing saves are upgraded at the next family tick by setting `walker.rec.ambientGreetings = true`; runtime child greetings are re-registered across age transitions and reapplied after async ambient config loading. Old family registrations are removed on world restoration so a previous child never leaks into another save.

Performance and diagnostics: this reuses the existing 5 Hz greeting scheduler and its bubble renderer; there is no new per-frame dialogue polling or new baby mesh. `AmbientDialogue.getDebug().lastBabySpeech` records the last rendered infant sound and whether the bubble used the parent-carried proxy; its existing Dev Companion ambient trace also reports the visible text. Tests `scripts/test-ambient-vocabulary.js` and `scripts/test-family-baby-burdens.js` cover growth-stage boundaries, saved-family restoration and all carry/throw transitions. `scripts/test-ambient-baby-dialogue.js` exercises the **real** ambient greeting renderer (with only canvas painting stubbed), including actual proximity scheduling, adult-text override, carried positioning, airborne ghost-bubble rejection, retry after an unavailable scene, and preservation of dynamic child greeting pools through an asynchronous config load.

Prior regression CI surfaced two stale test issues: a strict Node VM cross-realm array comparison after harvesting source words and an old head-turn assertion tied to a comment before this new infant-only branch. Both were corrected while keeping the original data and head-only-facing requirements. The full GitHub Actions result for the current branch head must be checked separately; a true mobile gameplay visual smoke check remains prudent before merging.

## Decoupled family voice integration
The independent `docs/js/family-baby-ambient-voice.js` module now owns newborn syllables, first toddler words, growth-phase registration, cleanup on world restore, and the visible carried-baby anchor. It queries `Shattercasks.getBurden('family_baby_' + childId)` and `FamilyBabyBurdens.carrying/isProxyActive` instead of adding a vocabulary method to the frozen family burden module. Its phase callbacks are thin `RomanceFamily` delegations; authoritative age, original Talk dialogue, and all of **main's posed-baby geometry** remain unchanged. `docs/js/ambient-dialogue.js` reuses the same bridge at its existing 5Hz scheduler, rather than introducing any new character polling. The original `scripts/test-family-baby-burdens.js` is preserved from main; separate `scripts/test-family-baby-ambient-voice.js` verifies speech anchoring and phase handoff, reducing future test-file conflicts.
